# DEPLOYMENT

## Prerequisites

- Node.js >= 20
- A funded wallet (VET for the account, **VTHO for gas**)
- `.env` configured from `.env.example` with **exactly one** signing strategy

## VeChain dual-token model (#9)

| Token | Role |
|---|---|
| **VET** | account / network asset (value, staking) |
| **VTHO** | pays transaction gas; generated by holding VET |

The deployment and anchor wallets need VTHO. Without fee delegation the anchor
wallet pays its own gas; with delegation a sponsor pays it. Do not assume
Ethereum's single-token gas model.

## 1. Thor Solo (local development)

```bash
docker run -d --name thor-solo -p 8669:8669 \
  vechain/thor:latest solo --api-addr 0.0.0.0:8669 --api-cors '*'
```

Solo pre-funds the well-known dev mnemonic accounts; no `.env` keys required.

```bash
npm run deploy:solo
npx hardhat test test/integration/vechain-solo.test.ts --network vechain_solo
```

The deployment record is written to `deployments/vechain_solo.json` (contract
address, network, chain ID, transaction ID, admin).

## 2. Testnet (#43)

```bash
cp .env.example .env
# Set VECHAIN_PRIVATE_KEY (testnet-only wallet!) or VECHAIN_MNEMONIC
```

Fund the wallet via the official VeChain testnet faucet (get VET + VTHO).
Then:

```bash
npm run deploy:testnet
```

Grant the anchor role with the **admin** wallet (the deployer is the initial
admin in this flow):

```bash
ROLE_OPERATION=grant ANCHOR_WALLET_ADDRESS=0xAnchorService... \
  npx hardhat run scripts/configure-roles.ts --network vechain_testnet
ROLE_OPERATION=check ANCHOR_WALLET_ADDRESS=0xAnchorService... \
  npx hardhat run scripts/configure-roles.ts --network vechain_testnet
```

Acceptance test: anchor `PF05043` V1 via the adapter or a test script, read
the anchor back, verify the `BatchAnchored` event, anchor V2, verify V1 is
unchanged, confirm `RootAlreadyAnchored` on replay. Do not proceed to mainnet
until this passes.

## 3. Mainnet (#8)

Deliberately guarded. Requires **all** of:

- `VECHAIN_MAINNET_CONFIRM=YES`
- `DEPLOYMENT_ADMIN_ADDRESS` (dedicated production admin, NOT the anchor wallet)
- a production wallet in `.env` (or migrated to HSM/Vault signer)

```bash
VECHAIN_MAINNET_CONFIRM=YES npm run deploy:mainnet
```

Post-deploy:

1. `ROLE_OPERATION=check` both wallets.
2. Record contract address + txId; verify source (see below).
3. Move the admin key to cold storage / multisig policy.
4. Fund the anchor wallet with VTHO (or configure a sponsor).

## Role configuration (#37)

```
ROLE_OPERATION=grant|revoke|check
ANCHOR_WALLET_ADDRESS=0x...
ANCHOR_CONTRACT_ADDRESS=0x...   # or use deployments/<network>.json
```

`grant` refuses nothing but warns when the target already holds admin rights;
production must keep admin and anchor wallets separate.

## Contract verification

VeChain Explorer (testnet/mainnet) supports flattened-source verification.
Use `@nomicfoundation/hardhat-verify` (included via the toolbox) against the
VeChain explorers or Sourcify once the network is supported there. Always
verify before mainnet anchoring goes live.

## Production checklist (#52)

```
[ ] VeChain SDK installed (@vechain/sdk-hardhat-plugin, current)
[ ] Archived VeChain plugins NOT used
[ ] Solidity 0.8.20 / shanghai / optimizer 200
[ ] OpenZeppelin AccessControl + Pausable only
[ ] vechain_solo / vechain_testnet / vechain_mainnet configured via env
[ ] Solo deployment + integration tests pass
[ ] Testnet deployment + acceptance pass
[ ] Admin/anchor wallet separation verified on-chain
[ ] ANCHOR_ROLE granted deliberately (not at deploy)
[ ] Duplicate protection + append-only behavior tested
[ ] Query functions verified while paused
[ ] BatchAnchored event indexing confirmed
[ ] No EPCIS / PII on-chain (commitments only)
[ ] Fee model + fee delegation documented
[ ] Static analysis (Slither) run, findings triaged
[ ] Gas reviewed (GAS_REPORT=true npx hardhat test)
[ ] .env not committed; production keys in HSM/Vault path
[ ] Contract source verified on explorer
```
